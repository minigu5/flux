# 부스 랜덤 뽑기 · 랭킹 앱 설계

날짜: 2026-09-04
저장소: minigu5/flux (Vercel 연결됨)

## 1. 목적

동아리 부스에서 사용할 단일 페이지 웹 앱이다. 아이들이 구조물 위에 물건을 쌓는
게임을 진행하는데, 이 앱이 두 가지 역할을 한다.

1. 쌓을 물건을 무작위로 뽑아 보여준다.
2. 참가자별 기록(쌓은 개수)을 랭킹으로 남긴다.

아이패드 한 대를 전체화면 브라우저로 띄워 부스 운영자와 참가자가 함께 본다.

## 2. 제약과 전제

- 표시 기기: 아이패드 1대, 브라우저 전체화면(가로 방향 가정).
- 서버 없음. 모든 상태는 브라우저 `localStorage`에 저장한다.
- 배포: Vercel. Next.js App Router의 기본 배포 경로를 그대로 쓴다.
- 물품 아이콘은 외부 CDN 이미지 링크를 사용한다. 이모지는 사용하지 않는다.
- 네트워크가 불안정할 수 있으므로 이미지 로딩 실패에 대비한 폴백이 필요하다.

## 3. 성공 기준

- 뽑기 버튼을 누르면 약 1.7초 동안 슬롯머신 연출이 돌고, 뽑힌 물품에 정확히
  멈춘다.
- 인원수를 1~5명으로 바꾸면 화면이 그만큼 좌우로 분할되고, 각 칸이 서로
  간섭하지 않는다.
- 뽑기를 여러 번 반복해도 특정 물품에 쏠리지 않고 10개가 고르게 나온다.
- 랭킹에 이름과 개수를 넣으면 개수 내림차순으로 정렬되어 보이고, 항목이 많아지면
  스크롤된다.
- 잘못 입력한 랭킹 항목을 삭제할 수 있다.
- 앱을 새로고침해도 랭킹과 뽑기 카운트가 유지된다.

## 4. 물품 목록

고정 10종이다. 순서는 표시 순서일 뿐 뽑기 확률과 무관하다.

| id | 이름 |
|----|------|
| `scissors` | 가위 |
| `glue` | 풀 |
| `ruler` | 자 |
| `booklet` | 책자 |
| `eraser` | 지우개 |
| `pencil` | 연필 |
| `calculator` | 공학용계산기 |
| `glasses-case` | 안경집 |
| `eclipse-tin` | 이클립스 통 |
| `lead-case` | 샤프심 통 |

각 물품은 `{ id, name, imageUrl, fallbackSvg }` 형태로 정의한다. `imageUrl`은 외부
CDN 링크이고, `fallbackSvg`는 로딩 실패 시 대신 그릴 인라인 SVG다.

## 5. 뽑기 규칙

사용자가 요구한 "적게 나온 쪽 선택" 방식을 그대로 구현한다.

1. 10개 물품 중 서로 다른 2개를 무작위로 고른다.
2. 두 후보의 누적 등장 횟수를 비교해 더 적은 쪽을 선택한다.
3. 횟수가 같으면 둘 중 하나를 무작위로 선택한다.
4. 선택된 물품의 누적 횟수를 1 증가시키고 저장한다.

이 규칙은 순수 함수 `drawItem(counts, random)`으로 구현한다. 난수 생성기를
주입받아 테스트에서 결과를 고정할 수 있게 한다.

카운트는 **슬롯별로 독립**이다. 슬롯 1의 뽑기 이력이 슬롯 2의 확률에 영향을 주지
않는다. 인원수를 줄였다가 다시 늘려도 해당 슬롯의 기존 카운트는 유지한다.

## 6. 화면 구성

### 6.1 플로팅 상단바

화면 상단에 떠 있는 알약 모양 바다. 항목은 `뽑기`와 `랭킹` 두 개뿐이다. 현재 탭은
배경이 채워진 상태로 표시한다. 스크롤과 무관하게 항상 같은 자리에 있다.

### 6.2 뽑기 탭

인원수 N(1~5)만큼 화면을 좌우로 균등 분할한다. 각 칸(슬롯)의 구성은 위에서부터
다음과 같다.

- 릴 창: 물품 이미지가 세로로 흐르는 영역. 위아래에 페이드 마스크를 넣어
  잘리는 느낌을 만든다.
- 물품 이름: 릴 아래에 크게 표시한다.
- 뽑기 버튼: 칸 하단에 배치한다. 애니메이션 중에는 비활성화한다.

각 슬롯은 자기 상태(현재 물품, 애니메이션 진행 여부, 카운트)만 가지며 다른 슬롯과
공유하지 않는다.

### 6.3 인원수 조절 버튼

화면 우측 하단의 작은 원형 버튼이다. 누르면 1~5 선택지가 펼쳐진다. 선택 즉시
분할 수가 바뀐다. 선택값은 `localStorage`에 저장한다.

### 6.4 랭킹 탭

- 중앙에 랭킹 목록을 세로로 표시한다. 개수 내림차순으로 정렬하고, 개수가 같으면
  먼저 등록한 항목이 위로 간다.
- 각 행에 순위, 이름, 개수, 등록 시각을 표시한다. 시각은 `HH:MM` 형식이다.
- 1·2·3위는 시각적으로 강조한다.
- 목록이 길면 목록 영역만 스크롤된다.
- 우측 하단 `+` 버튼을 누르면 입력 시트가 열린다. 이름은 텍스트 입력, 개수는
  0~10 숫자 칩 중 하나를 탭해서 고른다.
- 편집 모드 토글이 있다. 켜면 각 행에 삭제 버튼이 나타난다. 부스 현장에서 오타가
  나기 쉬우므로 삭제는 필요하지만, 평소에는 숨겨서 오탭을 막는다.

## 7. 슬롯머신 애니메이션

이 앱에서 가장 공들일 부분이다. CSS 키프레임 대신
`requestAnimationFrame` 루프로 릴 위치를 직접 계산한다. 뽑힌 물품에 정확히
멈춰야 하므로 정지 위치를 제어할 수 있어야 하기 때문이다.

동작은 다음과 같다.

- 릴은 물품 카드를 여러 번 반복해 이어 붙인 세로 스트립이다. 위치는
  `translate3d`로 옮긴다.
- 0.00s ~ 1.10s: 등속 고속 스크롤. 속도가 빠른 구간에서는 약한 모션 블러를 준다.
- 1.10s ~ 1.70s: `ease-out` 곡선으로 감속하면서 목표 인덱스에 정렬한다.
- 정지 순간: 살짝 지나쳤다가 되돌아오는 스프링 바운스를 넣고, 당첨 카드에 글로우
  펄스를 한 번 준다.
- 총 길이는 약 1.7초다.

애니메이션 진행 중에는 해당 슬롯의 뽑기 버튼을 잠근다. 다른 슬롯의 버튼은 영향을
받지 않는다.

`prefers-reduced-motion`이 켜진 환경에서는 연출을 짧은 페이드로 대체한다.

## 8. 데이터 모델과 저장

`localStorage` 키는 다음 세 개다.

| 키 | 내용 |
|----|------|
| `flux.playerCount` | 인원수 (1~5) |
| `flux.counts` | 슬롯 인덱스별 물품 등장 횟수 맵 |
| `flux.ranking` | 랭킹 항목 배열 |

랭킹 항목의 형태는 `{ id, name, count, createdAt }`이다. `id`는 `crypto.randomUUID()`로
만들고, `createdAt`은 epoch 밀리초로 저장한 뒤 표시할 때만 `HH:MM`으로 포맷한다.

저장 계층은 `lib/storage.ts`에 모은다. 이 모듈은 JSON 파싱 실패와 서버 사이드
렌더링 시점의 `window` 부재를 모두 흡수하고, 실패하면 기본값을 돌려준다.

## 9. 아이패드 대응

- 높이는 `100dvh`를 쓴다. 주소창 높이 변화에 대응하기 위해서다.
- `viewport-fit=cover`와 safe-area 인셋을 적용한다.
- `touch-action: manipulation`으로 더블탭 확대를 막는다.
- `user-select: none`으로 텍스트 선택 하이라이트를 막는다.
- `overscroll-behavior: none`으로 고무줄 스크롤을 막는다.
- 홈 화면 추가 시 전체화면으로 뜨도록 관련 meta 태그를 넣는다.
- 버튼의 최소 터치 영역은 44pt 이상으로 잡는다.

## 10. 모듈 구조

```
app/
  layout.tsx          루트 레이아웃, viewport/meta 설정
  page.tsx            탭 전환 셸
  globals.css         디자인 토큰, 리셋, 아이패드 대응
lib/
  items.ts            물품 10종 정의 (이름, CDN URL, SVG 폴백)
  draw.ts             drawItem 순수 함수
  storage.ts          localStorage 읽기/쓰기 래퍼
components/
  TopBar.tsx          플로팅 뽑기/랭킹 탭
  DrawTab.tsx         인원수만큼 슬롯 배치
  SlotMachine.tsx     릴 애니메이션 + 뽑기 버튼 (슬롯 1개)
  ItemImage.tsx       CDN 이미지 + onError SVG 폴백
  PlayerCountFab.tsx  우하단 인원수 조절 버튼
  RankingTab.tsx      랭킹 목록 + 편집 모드
  RankingSheet.tsx    이름/개수 입력 시트
```

각 컴포넌트는 자기 상태만 다루고, 공유가 필요한 값은 `page.tsx`에서 내려준다.
`SlotMachine`은 슬롯 인덱스와 카운트 갱신 콜백만 받으며 다른 슬롯을 알지 못한다.

## 11. 오류 처리

- CDN 이미지 로딩 실패: `ItemImage`가 `onError`를 잡아 인라인 SVG로 교체한다.
  물품 이름은 이미지와 별도로 렌더링하므로 어떤 경우에도 무엇이 뽑혔는지 알 수 있다.
- `localStorage` 접근 실패(사파리 프라이빗 모드 등): 저장 계층이 예외를 삼키고
  메모리 상태로만 동작한다. 앱은 계속 쓸 수 있고 새로고침 시에만 초기화된다.
- 저장된 JSON이 깨진 경우: 파싱 실패 시 기본값으로 되돌린다.
- 랭킹 이름이 빈 문자열이면 등록 버튼을 비활성화한다.

## 12. 테스트

- `lib/draw.ts`: 난수를 고정해 규칙 1~4를 각각 검증한다. 카운트가 같을 때와 다를
  때, 그리고 반복 실행 시 분포가 고르게 수렴하는지 확인한다.
- `lib/storage.ts`: 깨진 JSON, `window` 부재, 쓰기 실패 상황에서 기본값을
  돌려주는지 확인한다.
- 랭킹 정렬: 개수 내림차순, 동점 시 등록 순 유지를 확인한다.
- 애니메이션은 자동 테스트하지 않고 실기기에서 눈으로 확인한다.
